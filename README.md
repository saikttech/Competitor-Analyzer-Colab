


# 🚀 Competitor RAG Analyzer (Нейро-аналитик конкурентов)

[![Python 3.10+](https://img.shields.io/badge/python-3.10+-blue.svg)](https://www.python.org/downloads/)
[![OpenAI](https://img.shields.io/badge/OpenAI-API-412991.svg)](https://openai.com/)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](https://opensource.org/licenses/MIT)

**Competitor RAG Analyzer** — это автономный ETL и RAG (Retrieval-Augmented Generation) пайплайн для автоматического сбора, анализа и генерации отчетов по конкурентам в любой нише и географии. 

Проект реализован в формате Jupyter Notebook (Google Colab) с **Friendly UI**: пользователю достаточно запустить одну главную функцию, ввести нишу через `input()`, и система сама спарсит данные, очистит их от SEO-мусора, векторизует и выдаст структурированный аналитический отчет без галлюцинаций.

---

## ✨ Ключевые возможности

- 🕵️ **Умный парсинг**: Автоматический сбор данных конкурентов через DuckDuckGo с обходом базовых блокировок.
- 🧹 **Rule-based ETL**: Очистка `title` и `description` от SEO-спама, дублей гео и мусорных символов с помощью Regex.
- ✂️ **Смысловой чанкинг**: Разбиение текстов на фрагменты по границам предложений (Sentence-aware) для сохранения контекста.
- 🧠 **Векторный поиск (RAG)**: Использование `text-embedding-3-small` и косинусного сходства для поиска релевантных фактов.
- 🛡️ **Защита от галлюцинаций**: Строгий системный промпт, запрещающий LLM выдумывать факты, отсутствующие в контексте.
- 💾 **Автоматический экспорт**: Сохранение готового Markdown-отчета напрямую в Google Drive.
- 🛟 **Отказоустойчивость (Fallback)**: Автоматическая загрузка реалистичных демо-данных, если поисковик заблокировал IP облачной среды.
- 🧼 **Чистая архитектура**: Код разбит на изолированные «чистые функции» без использования глобальных переменных. Все пути параметризованы.

## 🛠 Технологический стек

* **Язык**: Python 3.10+
* **Среда выполнения**: Google Colab / Jupyter Notebook
* **База данных**: SQLite3 (локальное хранение чанков и метаданных)
* **Парсинг**: `duckduckgo-search` (ddgs), `BeautifulSoup4`
* **LLM & Embeddings**: OpenAI API (GPT-3.5-Turbo, text-embedding-3-small) через ProxyAPI
* **Математика**: `NumPy` (расчет косинусного сходства)
* **Интеграции**: Google Drive API, Google Colab Secrets

---

## 🏗 Архитектура пайплайна

Пайплайн состоит из 5 последовательных этапов, объединенных в главную функцию `main()`:

1. **Extract (Парсинг)**: Запрос к DuckDuckGo -> Сохранение сырых данных в SQLite.
2. **Transform (Очистка)**: Применение Regex-паттернов -> Удаление SEO-мусора.
3. **Transform (Чанкинг)**: Разбиение очищенных текстов на семантические блоки (до 500 символов).
4. **Load (Векторизация)**: Генерация эмбеддингов через OpenAI API -> Сохранение JSON-векторов в БД.
5. **Retrieve & Generate (RAG)**: Векторизация запроса пользователя -> Поиск топ-5 релевантных чанков -> Генерация отчета через LLM.

## 🚀 Быстрый старт (Google Colab)

Проект спроектирован для запуска в **Google Colab**. Весь код консолидирован в одной ячейке для удобства.

### 1. Подготовка
1. Откройте ноутбук `3_Parsing_ETL_Embedding_RAG_Отчет.ipynb` в Google Colab.
2. Перейдите в меню **Секреты (🔑)** на левой панели Colab.
3. Добавьте новый секрет:
   * **Name**: `OPENAI_API_KEY`
   * **Value**: Ваш API-ключ от OpenAI или ProxyAPI.ru
4. Убедитесь, что доступ к секрету для этого ноутбука включен (тумблер включен).

### 2. Запуск
Просто выполните **последнюю ячейку** ноутбука. Система сама:
* Подключит Google Drive.
* Спросит у вас Нишу, Географию и Поисковый запрос.
* Предложит очистить базу данных от предыдущих запусков.
* Выполнит полный цикл ETL и RAG.
* Сохранит итоговый отчет в папку `Competitor_DB/Reports` на вашем Google Диске.

## 🧪 Эксперименты и R&D

В файле [`Experiments_Report.md`](./Experiments_Report.md) подробно описаны 7 итераций разработки пайплайна, включая:

## ⚠️ Ограничения и Edge-Cases

* **Блокировки парсера**: Облачные IP-адреса Google Colab иногда блокируются поисковыми системами. В коде реализован `seed_demo_data()`, который подгружает эталонные данные, чтобы продемонстрировать работу RAG и LLM даже при недоступности парсера.
* **Лимиты API**: Векторизация 100+ сайтов требует времени и расходует токены OpenAI. В коде предусмотрены задержки (`time.sleep`) и коммиты в БД батчами для предотвращения разрывов соединения.
